Changelog

This file tracks changes to the ethdebug/format specification: the schemas under schemas/. Entries are grouped by the version of the @ethdebug/format package, which carries the spec version. Changes to the packages that implement the spec (@ethdebug/pointers, @ethdebug/evm, and so on) have their own release notes on GitHub Releases; this file covers only the spec itself.

Each entry gives a summary, in one or two sentences, of what changed. Three sub-items follow:

  • Schemas: the schema id(s) the change touches.
  • Producers: what an emitter of ethdebug/format data (a compiler such as solc or bugc) must change to keep emitting valid data, or no change needed.
  • Consumers: what a consumer of ethdebug/format data (a debugger such as soldb) must change to keep handling it correctly, or no change needed.

Unreleased​

Changed​

  • The offset field now carries past $wordsize into later slots instead of being bounded to a single slot, and length may span the resulting sequence of slots. The default length is now $wordsize - (offset mod $wordsize), running to the end of the slot in which the segment begins. A property lookup through $this (for example .length: "$this") must not be circular. New examples illustrate the carry (#284﻿).

    • Schemas: pointer/scheme/segment, pointer/expression
    • Producers: no change needed. Every previously valid pointer keeps its meaning; the change only removes an incorrect bound and defines behavior that was previously undefined.
    • Consumers: must resolve carried offsets and lengths that span slots, rather than assuming a segment stays within one slot.

  • Expressions now evaluate to one of two sorts, an unbounded integer or definite-width bytes, and the $concat and $keccak256 operands must be width-bearing bytes rather than bare integers. This tightens what was previously undefined; it does not break any output that was already valid, since the sorting rules were unstated before. Examples that hashed bare integers are corrected (#286﻿).

    • Schemas: pointer/expression
    • Producers: word-size bare integers (with $wordsized or a $sizedN form) before passing them to $concat or $keccak256; mapping-key pointers already do this.
    • Consumers: reject bare integers in $concat/$keccak256 operand positions, and treat arithmetic results as unbounded integers rather than assuming a fixed width.

0.1.0-1 — 2026-09-16​

Added​

  • A character encoding is a label defined by the WHATWG Encoding Standard, and an omitted optional encoding field means utf-8. materials/source and type/elementary/string both reference the new primitive instead of accepting a free-form string. (#285﻿)

    • Schemas: materials/encoding
    • Producers: emit the Standard's canonical lowercase label — utf-16le, not utf-16; utf-8, not UTF-8 or utf8.
    • Consumers: a label may go straight to new TextDecoder(label); the schema is still type: string, so a validator does not reject a non-Standard label.

  • A context may list the compiler transformations that produced an instruction — inline, tailcall, fold, coalesce, with an extensible identifier set and repeats allowed. A transform annotates rather than replaces the semantic contexts, and composes flat beside them on one context object. (#216﻿)

    • Schemas: program/context/transform
    • Producers: optional; emit it alongside the invoke/return bracket that an optimization would otherwise hide.
    • Consumers: no change needed; preserve an unfamiliar identifier as an opaque label, and optionally reconstruct inlined and tail-call activations that have no real frame.

  • An optional activation string pairs an invocation with the return or revert that ends it. Distinct activations carry distinct values, unique within the program. (#245﻿)

    • Schemas: program/context/function/invoke, program/context/function/return, program/context/function/revert
    • Producers: optional; put the same value on the opening invoke and on its closing return or revert.
    • Consumers: no change needed; where present, pair a call with its return by activation instead of relying on strict nesting in trace order.

  • Contexts mark the function-call lifecycle — an invocation of exactly one kind (jump for an internal call, message for an external message call, create for a contract creation), a successful return, or a revert — each carrying optional function identity (identifier, declaration, type). type/specifier names the "full type or { id } reference" pattern that type/wrapper and context variables now share. (#154﻿)

    • Schemas: program/context/function, program/context/function/invoke, program/context/function/return, program/context/function/revert, type/specifier
    • Producers: optional; for an internal call the invoke belongs on the callee's entry JUMPDEST, where the remaining stack is stable, and for an external call or creation on the CALL/CREATE instruction itself.
    • Consumers: read these to build a source-level call stack; type/specifier only names the discrimination that already existed, so type handling is unaffected.

  • A context may carry a name label, now wired into the context dispatcher; it is most useful for telling pick alternatives apart. (#179﻿)

    • Schemas: program/context/name
    • Producers: optional. Before this change the context schema's unevaluatedProperties: false rejected a name key outright, so the schema added in #113﻿ was unreachable.
    • Consumers: no change needed.

  • An array type may state a fixed element count; omitting it means the array is dynamically sized. (#168﻿)

    • Schemas: type/complex/array
    • Producers: emit count for fixed-size arrays, which the type schema previously had no way to express.
    • Consumers: treat a missing count as dynamic.

  • A pointer may declare templates inline with a templates/in pair, and a template reference may remap the region names a template produces through yields; unmapped names pass through unchanged. (#158﻿)

    • Schemas: pointer/collection/templates, pointer/collection/reference
    • Producers: optional; inline templates make a pointer self-contained, and yields lets one template be instantiated several times without region-name collisions.
    • Consumers: resolve a reference against inline templates first and the enclosing info pointers table second, then apply yields renames to the regions the template yields.

  • A { "$concat": [...] } expression evaluates to the concatenation of its operands' bytes, preserving each operand's byte width; an empty operand list is permitted. (#156﻿)

    • Schemas: pointer/expression
    • Producers: optional.
    • Consumers: implement $concat, adding and removing no padding between operands.

  • A pick lists two or more alternative contexts of which one holds, a gather lists two or more contexts that all hold simultaneously, and frame names the compilation frame ("ir", "source") a context's facts belong to. (#144﻿)

    • Schemas: program/context/pick, program/context/gather, program/context/frame
    • Producers: optional; reach for gather only where facts would collide on the same key, since disjoint keys compose flat on one object.
    • Consumers: resolve pick with runtime information, merge gather members, and filter or label contexts by frame.

  • One schema covers a non-negative integer given either as a JSON number or as a 0x-prefixed hex string; materials/source-range offsets and lengths, pointer/expression literals, and program/instruction offsets and operation arguments all reference it. (#126﻿)

    • Schemas: data/value
    • Producers: an instruction's operation.arguments items may now be JSON numbers, not only hex strings.
    • Consumers: accept both forms everywhere data/value appears — most notably operation arguments, which were hex-string-only before.

  • A context may carry a human-readable remark string, intended as annotation rather than as something a compiler interprets. (#125﻿)

    • Schemas: program/context/remark
    • Producers: optional.
    • Consumers: display it; derive no semantics from it.

  • One compilation's debugging information is a single info document holding its compilation, its programs, and by-name lookup tables for types and pointers. The same change raised the compilation id uniqueness requirement from should to must (relaxed back to should by #131﻿). (#123﻿)

    • Schemas: info, info/resources
    • Producers: emit one info document per compilation, hoisting shared types and pointer templates into the lookup tables.
    • Consumers: resolve { "id": ... } type references and named pointer templates against info.types and info.pointers.

  • A program describes one bytecode of a compilation — its contract, its environment (call or create), the context holding before its first instruction, and its instructions, each with an offset, an operation, and a context carrying source-range and variable facts. (#113﻿)

    • Schemas: program, program/instruction, program/context, program/context/code, program/context/variables, program/context/name
    • Producers: emit one program per bytecode; offset is the container-relative byte offset, which equals the program counter for legacy (non-EOF) bytecode but not for a code section within an EOF container.
    • Consumers: entirely new surface; nothing existing changes. program/context/name ships here but is unreferenced until #179﻿.

  • A pointer template is a pointer parameterised over the variables it lists in expect, and a { "template": ... } collection instantiates one by name. (#103﻿)

    • Schemas: pointer/template, pointer/collection/reference
    • Producers: optional; a repeated pointer shape can be emitted once and referenced rather than restated at every use.
    • Consumers: resolve a template reference by name and bind its expect variables from the instantiating scope.

  • Two primitives cover a 0x-prefixed hex string of at least one digit and a non-negative JSON integer. materials/source-range, pointer/expression, and the elementary numeric types reference them instead of restating the constraints. (#104﻿)

    • Schemas: data/hex, data/unsigned
    • Producers: type/elementary/bytes size now permits 0 (its minimum: 1 is gone), and the bits of int, uint, fixed, and ufixed must be integral rather than merely numeric.
    • Consumers: no change needed.

Changed​

  • An instruction's context is its postcondition — both its semantic facts and the pointers it contains resolve against the machine state after that instruction has executed. The program-level context is the base case of the chain: the precondition to instruction 0. (#281﻿)

    • Schemas: program/instruction, program
    • Producers: no change needed; this states the convention emission already followed. The Incrementer example is corrected to drop localValue from the ADD and following PUSH0 contexts, where ADD has consumed it.
    • Consumers: at the trace step about to execute instruction i, read instruction i − 1's context, or the program-level context before the first instruction. A debugger that had followed the removed sentence — which framed pointers as resolving against pre-execution state — must shift by one step.

  • Schema examples are corrected — a struct member's field is name, a list index is referenced bare rather than through $read, packed uint128 members are 16 bytes and not 128 — and additionalItems, which JSON Schema 2020-12 does not define, is dropped where it was inert. pointer/collection/scope's define validates its keys by referencing pointer/identifier rather than an inline copy of that pattern. (#277﻿)

    • Schemas: type/base, type/definition, pointer/collection/list, pointer/collection/scope, info/resources, program/context/function/invoke, program, info, pointer/template, program/context/gather, program/context/pick, program/context/variables
    • Producers: no change needed.
    • Consumers: no change needed; the accepted shape of every valid instance is unchanged.

  • The parameters wrapper and an external function's contract wrapper each accept an { id } type reference as well as a concrete type, matching what returns already allowed. (#279﻿)

    • Schemas: type/complex/function
    • Producers: parameters and the contract type may be given by reference instead of inline.
    • Consumers: resolve a reference in these positions like any other.

  • A name is an optional identifier, meant to be unique within a program, that today acts only as a label — the format defines no way to reference a context by name, so a declared name is inert. Establishing the identifier is groundwork for a future name-based pick selection. (#251﻿)

    • Schemas: program/context/name
    • Producers: no change needed.
    • Consumers: no change needed.

  • The target field is optional on an internal (jump) invocation, for the cases with no meaningful target pointer — most notably the first instruction of an inlined body, whose JUMP has been elided. External calls and contract creations still require it. (#242﻿)

    • Schemas: program/context/function/invoke
    • Producers: omit target rather than emit a placeholder pointer; the callee identity stays meaningful without it.
    • Consumers: handle an invoke context with no target.

  • The data field is optional, so a bare return: {} is permitted where a return is known to happen but no return value is observable — a void function, or a tail-call-optimized back-edge. (#211﻿)

    • Schemas: program/context/function/return
    • Producers: omit data instead of pointing at stack slot 0, which at a TCO back-edge holds the next iteration's argument, not the return value.
    • Consumers: handle a return context with no data.

  • An id identifies a compilation resource such as a source file or a compilation, may be numeric or a string, and must be unique within the scope where it appears — source ids within one compilation, for instance. (#172﻿)

    • Schemas: materials/id
    • Producers: no change needed.
    • Consumers: no change needed.

  • The array type schema carries a description of itself, of contains, and of each of its examples. (#170﻿)

    • Schemas: type/complex/array
    • Producers: no change needed.
    • Consumers: no change needed.

  • The context schema dispatches on each property with if/then clauses instead of an anyOf over the member schemas, so a general-purpose validator reports one error against the relevant member rather than a failure of the whole union. (#150﻿)

    • Schemas: program/context
    • Producers: no change needed for a well-formed context.
    • Consumers: no change needed.

  • An empty context ({}) is valid, and both the program-level context and an instruction's context are optional, with omission equivalent to {}. (#145﻿)

    • Schemas: program, program/instruction, program/context
    • Producers: omit context on an instruction that carries no facts instead of inventing one.
    • Consumers: treat a missing context as the empty context — an instruction's context is no longer guaranteed present.

  • A compilation's id is described as its identifier rather than as optional, and its uniqueness requirement returns to should after #123﻿ had raised it to must. The required list is not actually changed here; #138﻿ does that. (#131﻿)

    • Schemas: materials/compilation
    • Producers: start emitting id on every compilation.
    • Consumers: no change needed.

  • The range field may be omitted as shorthand for a range spanning the entire source contents, and is otherwise required. (#107﻿)

    • Schemas: materials/source-range
    • Producers: optional shorthand; previously range was always required.
    • Consumers: treat a source range with no range as offset 0 through the full length of the referenced source's contents.

Breaking​

  • An object whose property set the format fully defines rejects unknown properties. materials/compilation's settings object stays open, since it holds settings in a format native to the compiler, and info/resources stays lax when validated alone because info composes it by $ref. (#280﻿)

    • Schemas: info, program, program/instruction, materials/compilation, materials/source, program/context/function/return, program/context/function/revert, pointer/collection/list
    • Producers: drop extension keys from these objects; a misspelled or extra key is now a validation error instead of silently accepted. Compiler-native extension data belongs in settings.
    • Consumers: no change needed.

  • An elementary type must not carry contains, which is what discriminates it from a complex type; a function complex type requires kind and contains; contract's library and interface flags are booleans; a context name must be non-empty; and a region requires location. (#279﻿)

    • Schemas: type/elementary, type/complex/function, type/elementary/contract, program/context/name, pointer/region
    • Producers: output that relied on any of these gaps no longer validates — {kind: bool, contains: ...}, {external: true} alone, {kind: function, internal: true} with no contains, {kind: contract, library: true, interface: 42}, and name: "".
    • Consumers: no change needed; each fix rejects an instance that was never meaningful. A location-less region now produces one clear error rather than implicating all seven region types at once.

  • A compilation's id is required. (#138﻿)

    • Schemas: materials/compilation
    • Producers: emit id on every compilation. #131﻿ had declared this in prose but left it out of required.
    • Consumers: id may now be relied on as present.

  • A variable object must carry at least one property, and must not carry properties the format does not define. (#127﻿)

    • Schemas: program/context/variables
    • Producers: drop extension keys from variable objects, and emit no empty variable entries.
    • Consumers: no change needed.
